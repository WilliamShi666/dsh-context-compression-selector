### 2.2 块长度公式（冻结）

**规则 R2.3**：`deepSeekVisionImageBlockTokens(nLlmH, nLlmW, startTokenPos)` 的返回值**恰好**为：

```
nLlmH * (nLlmW + 1) + 2
```

**规则 R2.4（必须移除的项）**：实现中**不得**存在以下任何加项，且模块级常量 `COMPRESS_PAD_TO` **必须删除**：

| 已移除项 | 旧公式中的作用 |
| --- | --- |
| compress pad | `COMPRESS_PAD_TO - 1 - startTokenPos % COMPRESS_PAD_TO` |
| 前导 sentinel | `+ 1`（IMAGE_START） |
| odd-row pad | `nLlmH % 2 === 1 ? nLlmW + 1 : 0` |
| alignment pad | `(Math.floor(rows/2) * rowLen % 2) * 2` |
| 尾部 sentinel | `+ 1`（IMAGE_END） |

（`nLlmH * (nLlmW + 1)` 已内含每行 1 个 IMAGE_NEW_LINE，`+ 2` 已内含 IMAGE_START 与 IMAGE_END；见官方 `num_image_tokens` 与 `image_token_types`。）

**规则 R2.5（`startTokenPos` 惰性）**：`startTokenPos` 参数**必须保留**在签名中（保持调用图不变），但其值**不得**影响返回值。判定式（对任意 `nLlmH,nLlmW ≥ 1` 与任意整数 `p,q`）：

```
deepSeekVisionImageBlockTokens(nLlmH, nLlmW, p) === deepSeekVisionImageBlockTokens(nLlmH, nLlmW, q)
```

**规则 R2.6**：`deepSeekVisionImageTokens(width, height, startTokenPos)` 同样保留三参签名，且其返回值**不依赖** `startTokenPos`。

### 2.3 网格与 resize 算术（冻结）

**规则 R2.7（`deepSeekVisionImageGrid`）**：按官方 `plan_image_grid` 顺序执行，**无** `visionMaxWhRatio` 钳制分支：

1. 若 `0 < width*height < 295936`：`ratio = (295936 / (width*height)) ** 0.5`；`width = trunc(width*ratio)`；`height = trunc(height*ratio)`。
2. `bestWidth = ceil(width / 14) * 14`；`bestHeight = ceil(height / 14) * 14`。
3. `safeResize(height, width, bestHeight, bestWidth)`。

**规则 R2.8（`safeResize` 单次求解，无循环）**：

```
nLlmH = ceil(floor(bestHeight / 14) / 3)
nLlmW = ceil(floor(bestWidth  / 14) / 3)
若 nLlmH*(nLlmW+1)+2 > 1024:
    (bestHeight, bestWidth) = solveResizeRatio(height, width)   # 仅一次，无 budget 递减循环
    nLlmH = ceil(floor(bestHeight / 14) / 3)
    nLlmW = ceil(floor(bestWidth  / 14) / 3)
    断言 nLlmH*(nLlmW+1)+2 <= 1024
```

**captain 裁定（对 R2.8 的有意偏离）**：本实现**不移植**上述 `assert num_image_tokens(n_llm_h, n_llm_w) <= max_n_token`，属对 R2.8 的**有意偏离**，理由：

1. V4.1 下 `max_n_token` 恒为 `1024`，且 `safeResize` 为单次闭式求解（无 budget 递减循环），该断言在参数域内**不可达**。
2. 执行者以 **646,000** 组尺寸扫描（退化尺寸、`min_pixels = 295936` 阈值邻域、极端长宽比、seeded random），**0 例违例**，最坏情况恰好 `1024`。
3. 增加一个不可达断言不产生可观测防护，却引入无测试可覆盖的分支。

该偏离已同步记录于 `packages/runtime/src/deepseek-v4-vision-tokens.ts` 的 `solveResizeRatio` 文档注释，以及 `packages/runtime/tests/fixtures/PROVENANCE.md`。本裁定不免除 R2.8 的其余义务（单次求解、无循环）。

**规则 R2.9（`solveResizeRatio` 单次求解，官方形式）**：

```
r          = height / width
maxW_float = sqrt((1024 - 2) / r + 0.25) - 0.5
maxH_float = maxW_float * r
cell       = 14 * 3 = 42
若 maxW_float < 1.0:  返回 ( (1024-2)//2 * 42 , 42 )        # 极瘦高：单列
若 maxH_float < 1.0:  返回 ( 42 , (1024-3) * 42 )           # 极扁宽：单行
否则:
    beta = min( floor(maxW_float)*42 / width , floor(maxH_float)*42 / height )
    返回 ( floor(height * beta / 14) * 14 , floor(width * beta / 14) * 14 )
```

**规则 R2.10**：旧实现中的 `gridTokens()`（含 odd-row pad 与 alignment pad 的 N-layout 占用检查）**必须删除**；占用检查改用 `num_image_tokens(nLlmH, nLlmW) = nLlmH*(nLlmW+1)+2`。

### 2.4 估算器（冻结）

**规则 R2.11**：`estimateDeepSeekVisionImageTokens(width, height)` 返回形状不变（`tokens` / `upperBoundTokens` / `source` / 可选 `paddingMinimumTokens` / `paddingMaximumTokens`），但：

- `upperBoundTokens` 恒为 `1024`（旧值 `384`）。
- `source === 'intrinsic-grid'` 时：因块长度与位置无关，四个残差计数**全部相等**，故
  `paddingMinimumTokens === paddingMaximumTokens === tokens`。
- `source === 'default'`（无效/不安全元数据）时：`tokens === 256`（`DEEPSEEK_VISION_DEFAULT_IMAGE_TOKENS` **保持 256**），`upperBoundTokens === 1024`，**不**返回 `paddingMinimumTokens` / `paddingMaximumTokens`。

| 常量 | 旧值 | 新值（冻结） |

```
allowHistory === (reclaimedLowerBoundTokens * hit) > (affectedHitUpperBound * (miss - hit))
```

旧价 `hit=0.007`/`miss=0.22` → 每 token 惩罚 `miss-hit = 0.213`、阈值 `hit/(miss-hit) = 0.032864`；Flash 价 `hit=0.003`/`miss=0.15` → 惩罚 `0.147`、阈值 `0.020408`。**Flash 价更严格**（History 更少被允许）。已实测翻转样例（`reclaimed=1000, affected=25`）：旧价 ALLOW → Flash 价 deny；`(10000,250)` 与 `(5000,140)` 同样翻转。故若沿用旧价，`deepseek-v4-flash` 路由上的 adaptive 决策会**与官方计费口径相反**。
